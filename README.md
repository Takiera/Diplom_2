# Stellar Burgers — API-тестирование

**Java · REST Assured · JUnit 4 · Allure**

Учебный проект Яндекс Практикума.

В проекте проверяется регистрация, вход и создание заказа, эти процессы представлены позитивными и негативными API-сценариями с проверкой HTTP-статусов и JSON.

## Подход к тестированию

- **Обязательные поля:** отдельные сценарии для регистрации без email, пароля и имени.
- **Негативные условия:** повторная регистрация, неверные учетные данные и некорректные ингредиенты.
- **Авторизация:** сравнение создания заказа с токеном и без него.
- **Проверки ответа:** assertions для HTTP-статусов, признака успеха и сообщений об ошибках.
- **Разделение ответственности:** модели запросов, API-действия и проверки находятся в отдельных слоях.
- **Отчетность:** Allure описывает шаги сценариев и их результаты.

## Технологии

- Java;
- JUnit 4;
- REST Assured;
- Allure.

## Что проверяется

### Регистрация

- Создание пользователя с заполненными обязательными полями.
- Повторная регистрация пользователя.
- Регистрация без email, пароля или имени.

### Авторизация

- Вход с корректными учетными данными.
- Вход с неверным email.
- Вход с неверным паролем.

### Заказы

- Создание заказа с авторизацией и без нее.
- Создание заказа с пустым списком ингредиентов.
- Создание заказа с некорректными идентификаторами ингредиентов.

## Структура

```text
src/main/java/data/            # адреса API и исходные данные
src/main/java/model/           # модели запросов
src/main/java/steps/           # действия с API
src/test/java/                 # сценарии и настройка окружения
pom.xml                        # зависимости и плагины
```

## Запуск

Скачайте исходники `main`, распакуйте их и откройте терминал в каталоге с `pom.xml`.

```bash
mvn clean test
```

Базовый адрес API задан в `src/main/java/data/UserData.java`.

## Allure

Сформировать отчет по имеющимся результатам:

```bash
mvn allure:report
```

Открыть отчет локально:

```bash
mvn allure:serve
```
